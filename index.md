# CS 499 Professional Self-Assessment
When I first started working toward my Computer Science degree at Southern New Hampshire University, I had a different understanding of what working in IT involved. I mostly thought about working with computers, repairing hardware, setting up systems, and troubleshooting problems. As I went through the program, I learned that computer science involves much more than that. I started learning about programming, software development, databases, security, and how different parts of a computer system work together.
My career goal is to find a job in IT that allows me to work remotely. I would also like to eventually start my own computer repair business. Both of these goals have influenced the projects I have worked on and the skills I have tried to improve throughout the program.
Throughout the Computer Science program, I gained experience working with different programming languages, understanding how software works, and finding ways to solve problems. I also learned that there is usually more than one way to accomplish something. Sometimes a solution works, but that does not always mean it is the best way to do it. I had to think about how my code was organized, how information was handled, and what could happen when changes were made.
Most of the projects I completed throughout my Computer Science program were individual assignments. This meant I was responsible for planning, writing the code, troubleshooting problems, and testing my work. Even though I was working independently, I learned how important communication and collaboration are in software development.
Throughout the program, I received feedback from my instructors and used it to improve my projects. I also learned how to explain the changes I made and why I made them. These are skills I would need when working with other developers, IT support teams, or customers. Working independently also taught me how to manage my time and solve problems without depending on someone else to do the work.
I improved my ability to explain technical work as well. For my capstone project, I had to describe the changes I made, why I made them, and how they improved the application. Being able to explain technical information is important because not everyone I work with will have the same level of computer knowledge. This is something I expect to use whether I am working remotely in IT or helping customers with computer problems.
Another area where I improved was understanding data structures and algorithms. I learned that how information is organized can affect how easily an application can find and use it. Searching, filtering, and sorting information gave me a better understanding of how an application can work with records instead of just displaying everything in the order it was entered.
I also learned that changing the order of information can create problems if the program depends on where an item is located in a list. This helped me understand why it is important to use reliable ways of identifying information and to consider what happens when the user searches or sorts records.
Software engineering was another important part of the program. I learned more about organizing code, creating different parts of an application, and making those parts work together. I also gained experience with databases and learned why information needs to be stored in a way that allows it to be retrieved and updated correctly. These are skills I can use in different types of IT work, not just mobile application development.
Security was another area that changed how I thought about software. In my SNHU Investments security project, I worked with a C++ application and examined areas where the code could have security vulnerabilities. This helped me understand why developers need to think about security while designing and maintaining software rather than waiting until a problem happens.
I learned that protecting information involves more than simply saving it in a database. Password handling, access to information, and the way a program processes user input can all affect security. These are things I would need to consider when working with customer information or supporting computer systems.
Throughout the Computer Science program, I also learned more about problem-solving. There were times when something worked in one part of an application but caused a problem somewhere else. I had to go back through the code, figure out what was happening, make changes, and test the application again. This taught me that developing software is not just about writing code. It also involves testing, finding mistakes, and improving what has already been created.
One of the biggest things I learned was how to take something I had already created and improve it instead of starting over. For my capstone project, I chose an Android inventory tracking application that I had developed in an earlier course. The original app was designed to manage inventory, but I wanted to turn it into something that could eventually be used in a computer repair business.
For my first enhancement, I focused on software design and engineering. I changed the application so it could manage customer repairs along with computer parts. I added a dashboard that separates new repairs, existing repairs, and parts inventory. I also worked on screens that allow repair information to be entered, viewed, and updated. This gave me more experience with software design and helped me understand why it is important to organize an application so that it is easier to use and maintain.
For my second enhancement, I focused on algorithms and data structures. I worked on the way the application searches, filters, and sorts repair records. This made it easier to find a particular customer or repair without having to go through every record manually. I also had to think about how the application identifies records when the order of the list changes. This helped me understand that the way information is handled behind the scenes is just as important as what the user sees.
For my third enhancement, I focused on databases. I learned that it was not enough to have screens that allowed someone to enter information. The information also needed to be saved correctly and available when the application was opened again. I used SQLite to store repair records and added the ability to create, read, update, and delete information.
One problem I ran into was making sure the correct repair opened after the order of the list changed. I solved this by using the database ID assigned to each repair instead of relying on its position in the list. I also tested the application by closing it and opening it again to make sure the repair information was still there.
During the database work, I also improved how the application handles passwords by changing from SHA-256 hashing to PBKDF2 with individual random salts. I wanted to improve security without requiring existing users to create new accounts. This gave me more experience thinking about how security improvements can affect the people using an application.
One thing I like about my capstone project is that it connects to something I would actually like to do in the future. If I eventually open my own computer repair business, I would need a way to keep track of customers, repairs, and computer parts. Building this application gave me a chance to work on something that could eventually help with that goal.
My first goal after graduation is to find a remote IT position where I can continue building my experience. I am interested in troubleshooting, supporting computer systems, and continuing to improve my technical skills. Over time, I would like to use that experience to help me start my own computer repair business.
Looking back at the program, I can see how much my understanding of computer science has changed. I started with more of an interest in computer hardware and repair, but I now have a better understanding of software development and how programming can be used to solve problems. I still have more to learn, but I feel that the projects I completed have given me a foundation that I can continue building on.
The artifacts in my ePortfolio show that progress. They demonstrate how I have worked on software design, algorithms and data structures, organizing and managing data, improving security, and solving problems through testing and changes to my code. They also show how I was able to take an application from an earlier course and continue developing it into something more useful.
Completing this program has helped me see more possibilities for my future in IT. Whether I am working remotely for a company or eventually running my own repair business, I plan to continue learning and improving my skills as technology changes.
